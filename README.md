## Прототип

Четыре роли на **одном состоянии**: действие сопровождающего немедленно видно
родителю и дежурному. Переключатель ролей и демо-сценарии спрятаны за полосой
**«Демо-стенд»** сверху — свёрнута по умолчанию, чтобы первым экраном человек
видел продукт, а не пульт показа. В свёрнутом виде полоса подписана текущей ролью.

**Сквозной сценарий, ради которого он собран:**

1. **Родитель** видит «Миша в пути»: карта, этап словами, последняя точка с честным «получено N сек назад».
2. **Сопровождающий** → «Открыть» → проходит машину состояний до передачи. Без фото и без принимающего из белого списка передача не закрывается.
3. **Родитель** получает «Миша дошёл ✓» — сообщением в MAX и доказательством: время, кто принял, фото, журнал переходов.
4. **Требует внимания** → пятница без сопровождающего → подбор по коридору → одобрение → первый путь вместе.
5. **Дежурный** (тёмный пульт) — лента инцидентов от детекторов. Кнопка «Сценарий: пропал сигнал» в демо-панели через 25 секунд сама открывает инцидент.
6. **Координатор школы** — покрытие по классам и рассылка в чат класса.
7. **Проверка личности** — «Профиль» → карточка проверки. Шесть уровней, у каждого
   своя кнопка, за которой стоит настоящий метод MAX. Вне мессенджера каждая
   честно объясняет, что произойдёт внутри него.
8. **Порог** — пятница, подбор: Тимур лучший по коридору, но без справки о
   несудимости. Кнопка «Всё равно одобрить» есть — и она отказывает.

## Разделение продуктов

Два приложения, одна база данных, разные вопросы.

| | Нативный «Заступник» | Мини-апп в MAX |
|---|---|---|
| Отвечает на вопрос | Где сейчас ребёнок | Кто этот человек и как его заказать |
| Геопозиция | Фоновый трекинг, живая карта | **Нет.** Показывает последнюю точку, пришедшую с сервера |
| Верификация | — | Лестница доверия, шесть уровней |
| Заказ и подбор | — | Маршруты, кандидаты, одобрение, статусы |
| Почему так | Фоновая гео в webview невозможна в принципе | В мессенджере у человека уже есть подтверждённый российский номер |

Разделение снимает главное техническое препятствие: мини-аппу больше не нужно
притворяться, что он умеет трекинг. Он делает то, что умеет лучше нативного
приложения, — проверяет людей там, где они уже авторизованы.

## Лестница доверия

«Проверен» без указания уровня — обещание, а не факт. Шесть уровней, каждый
отвечает на свой вопрос и стоит своего времени. Порог для того, кто ведёт
чужого ребёнка, — **несудимость**; ниже него кандидат виден, но недоступен,
и это проверяется не кнопкой в интерфейсе, а сервером.

| Уровень | Вопрос | Чем подтверждается | Цена |
|---|---|---|---|
| Аккаунт MAX | Есть ли живой аккаунт | Подпись `initData`, сверка с токеном бота | мгновенно |
| Номер телефона | Чей это номер | `requestContact()`, хеш сверяется с токеном бота | мгновенно |
| Личность | Как его зовут | Вход через Госуслуги (ЕСИА); на пилоте — банк-ID или модерация | минуты |
| Несудимость | Можно ли к детям | Справка МВД из Госуслуг, подписанная ведомством | до 30 дней |
| Свой в школе | Откуда он здесь | Координатор подтверждает факт обучения | дни |
| Живость на выходе | Он ли это сегодня | Биометрия устройства перед выходом на маршрут | каждый раз |

**Чего в MAX нет.** Мессенджер не отдаёт мини-приложению признак «пользователь
подтверждён на Госуслугах» — такого поля в Bridge API не существует. Связка
MAX ↔ Госуслуги работает в обратную сторону: MAX служит вторым фактором для
входа **на** Госуслуги. Регистрация в MAX идёт по номеру телефона, и
единственное, что мессенджер даёт бесплатно, — это подтверждённый номер.
Личность придётся подтверждать самим.

**Про ЕСИА честно.** Подключение информационной системы коммерческой
организации к ЕСИА требует аттестации по требованиям информационной
безопасности и СКЗИ класса КС3, плюс учётной записи юрлица, подтверждённой
УКЭП. Это месяцы, а не спринт. Поэтому уровень «Личность» на пилоте
закрывается банковским ID или ручной модерацией, а ЕСИА остаётся целью.

Авторизация по российскому номеру телефона — законный способ по ч. 10 ст. 8
149-ФЗ в редакции 406-ФЗ, так что базовый уровень не требует ничего сверх
того, что MAX уже умеет.

## Слой MAX

Подключён по живой документации [dev.max.ru/docs/webapps](https://dev.max.ru/docs/webapps/bridge), а не по догадке. Библиотека `max-web-app.js` грузится с `st.max.ru` и кладёт в `window` объект `WebApp`; отдельная инициализация не нужна — ни `ready()`, ни `expand()` в MAX нет. Весь контакт с мессенджером — в объекте `maxBridge`.

| Что | Метод MAX |
|---|---|
| Кто открыл приложение | `initDataUnsafe.user` |
| Из какого чата открыли (для координатора это чат класса) | `initDataUnsafe.chat` |
| Приглашение класса по ссылке | `initDataUnsafe.start_param` |
| Отклик на действие / на результат | `HapticFeedback.impactOccurred` / `notificationOccurred` |
| Рассылка в чат класса | `shareMaxContent({text, link})` |
| Кнопка «назад» в шапке мессенджера | `BackButton` ← стек экранов |
| Защита незаконченного мастера маршрута | `enableClosingConfirmation` |
| Подтверждение номера телефона | `requestContact()` + сверка хеша на сервере |
| Живость сопровождающего перед выходом | `BiometricManager.authenticate()` |
| Вход через Госуслуги и заказ справки | `openLink()` — внешний браузер, OAuth не живёт в webview |
| Переход в нативный «Заступник» за картой | `openLink()` / `openMaxLink()` |
| Подтверждение передачи ребёнка | `openCodeReader(false)` — QR у встречающего |
| Экраны с данными ребёнка | `ScreenCapture.disableScreenCapture()` |

Вне MAX объекта `WebApp` нет, и приложение работает в демо-режиме — поэтому `index.html` по-прежнему открывается двойным щелчком.

**Авторизация.** `initDataUnsafe` годится только для отрисовки. Доверять запуску можно после проверки строки `initData` на бэкенде: `HMAC_SHA256(HMAC_SHA256('WebAppData', botToken), параметры)`. Бэкенда в прототипе нет — это первая серверная задача.

## Деплой в MAX

Мини-приложение в MAX не существует само по себе — оно всегда открывается из чат-бота. Подключение к платформе доступно юрлицам, ИП и самозанятым — резидентам РФ.

### 1. Хостинг — GitHub Pages

Репозиторий здесь уже заведён, первый коммит сделан. `CONCEPT.md` **намеренно исключён** в `.gitignore`: бесплатные Pages работают только из публичного репозитория, а продуктовая стратегия в публичный доступ не едет.

Репозиторий — [github.com/Glabgi/zastupnik](https://github.com/Glabgi/zastupnik), публичный, без README и .gitignore при создании (иначе первый push упрётся в конфликт).

```bash
git remote add origin git@github.com:Glabgi/zastupnik.git && git push -u origin main
```

Затем в репозитории **Settings → Pages → Source: Deploy from a branch → `main` / `(root)`**.

Через минуту приложение будет доступно по адресу:

```
https://glabgi.github.io/zastupnik/mvp/
```

Этот же адрес вставляется в настройки бота в MAX.

### 2. Бот и регистрация URL

На [business.max.ru/self](https://business.max.ru/self) создайте бота, затем **Чат-боты → бот → ⋮ → Настройки**, вставьте адрес выше и выберите вид кнопки запуска.

Требования к URL: только `https://`, до 1024 символов, латиница, цифры, точка и дефис.

### 3. Имя бота в коде

Подставьте его в `BOT_NAME` ([mvp/app.inner.html](mvp/app.inner.html)) и пересоберите — из этой константы собираются все диплинки.

**Диплинки.** `https://max.ru/<бот>?startapp=<payload>`, payload до 512 символов, только латиница, цифры, `_` и `-`.

| Ссылка | Что откроется |
|---|---|
| `?startapp=class_sch1-2b` | вход родителя по приглашению класса |
| `?startapp=role_duty` | пульт дежурного — для показа без прокликивания |

## Что осталось замокано

- **Сама проверка.** Уровни хранятся в состоянии страницы. В проде их держит
  сервер: он сверяет подпись `initData`, хеш номера и подпись МВД на справке.
  Клиент только показывает результат — иначе «проверку» можно нарисовать себе
  самому через консоль, что в прототипе и происходит.
- **Картография** — стилизованная SVG-схема. В проде — MapLibre и собственный экстракт карты на своих серверах.
- **Геопозиция** — движение точки симулируется таймером. Фоновая гео в webview невозможна; она живёт в нативном приложении «Заступника».
- **Шрифты** грузятся с Google Fonts — для российской аудитории лучше положить `.woff2` рядом с приложением. Без них интерфейс уходит на системный шрифт, но остаётся рабочим.
- **Оплата, страхование, публикация в сторах** — вне MVP.
